==============================================================================
FIREBASE SECURITY RULES - COPY THESE TO YOUR FIREBASE CONSOLE
==============================================================================

INSTRUCTIONS:
1. Go to: https://console.firebase.google.com/
2. Select your project: dnd-initiative-roller
3. Click "Realtime Database" in the left menu
4. Click the "Rules" tab at the top
5. Replace ALL existing rules with the rules below
6. Click "Publish"

==============================================================================
RECOMMENDED RULES (Most Secure - Campaign-Level Access):
==============================================================================

{
  "rules": {
    "campaigns": {
      "$campaignId": {
        ".read": "auth != null",
        ".write": "auth != null",
        ".validate": "newData.hasChildren(['meta', 'data'])",
        "meta": {
          ".validate": "newData.hasChildren(['name', 'lastUpdated'])",
          "name": {
            ".validate": "newData.isString() && newData.val().length > 0 && newData.val().length <= 100"
          },
          "lastUpdated": {
            ".validate": "newData.isNumber()"
          }
        },
        "data": {
          ".validate": "newData.hasChildren(['currentRound', 'lastUpdated'])",
          "currentRound": {
            ".validate": "newData.isNumber()"
          },
          "lastUpdated": {
            ".validate": "newData.isNumber()"
          }
        }
      }
    },
    ".read": false,
    ".write": false
  }
}

==============================================================================
ALTERNATIVE: SIMPLER RULES (Still Secure):
==============================================================================

If the above rules cause issues, use these simpler ones:

{
  "rules": {
    "campaigns": {
      "$campaignId": {
        ".read": "auth != null",
        ".write": "auth != null"
      }
    }
  }
}

==============================================================================
WHAT THESE RULES DO:
==============================================================================

RECOMMENDED RULES:
- Only authenticated users can access campaigns
- Data structure is validated (prevents malformed data)
- Campaign names must be 1-100 characters
- Root-level access is denied (only /campaigns/ is accessible)
- Prevents writing invalid data structures

IMPORTANT: The data validation only requires 'currentRound' and 'lastUpdated'.
Do NOT require 'combatants' or 'initiativeHistory' - the Realtime Database
strips empty arrays from writes, so a campaign with no combatants (or no
history yet) would fail validation and silently stop syncing. This is exactly
the state every newly created campaign starts in.

SIMPLER RULES:
- Only authenticated users can access campaigns
- No data validation, but still secure
- Easier to troubleshoot if issues arise

==============================================================================
WHY FIREBASE IS SENDING WARNINGS:
==============================================================================

Firebase flags rules as "insecure" when:
1. Any authenticated user can read/write everything (current setup)
2. There's no user-specific access control
3. Data isn't scoped to individual users

With ANONYMOUS auth (the old setup) this warning was accurate: anyone could
sign in anonymously and read/write everything. The app now uses EMAIL/PASSWORD
sign-in with a single shared account and no public sign-up (see below), so
"auth != null" really means "someone who knows the password". Firebase's
automated scanner cannot see that distinction, so the warning email may still
arrive - at that point it is a false positive and safe to mute
(Project Settings -> email preferences).

This shared-account model fits this app because all DM devices and players
need access to all campaigns.

==============================================================================
SET UP EMAIL/PASSWORD AUTHENTICATION (required):
==============================================================================

The app signs in with a single shared account. The email is hardcoded in
app.js (AUTH_EMAIL) and is not a secret or a real inbox; the password is what
users type at the login screen and is verified by Firebase, never stored in
the code.

1. In Firebase Console, click "Authentication" in the left menu
2. Go to the "Sign-in method" tab
3. Enable the "Email/Password" provider (leave "Email link" off)
4. DISABLE the "Anonymous" provider (the app no longer uses it)
5. Go to the "Users" tab and click "Add user"
   - Email: the AUTH_EMAIL value from app.js
     (currently dm@dnd-initiative-roller.firebaseapp.com)
   - Password: the app password you want everyone to type at login
6. To change the password later: delete and re-add the user (or use the
   password reset flow), then everyone signs in again with the new one

Do NOT enable any self-service sign-up UI - this project has none, and the
Firebase project should contain only this one user. In Authentication ->
Settings -> User actions, uncheck "Enable create (sign-up)" if available, so
nobody can create additional accounts via the API.

==============================================================================
TESTING:
==============================================================================

After applying the RECOMMENDED rules:
1. Try accessing your app - should work normally with password
2. Create/edit campaigns - should work fine
3. Try accessing Firebase URL directly - should be denied
4. Check Firebase Console for any error messages

After applying the SIMPLER rules:
1. Everything should work exactly as before
2. Firebase warnings may still appear (the scanner can't tell that sign-up
   is closed) - safe to mute
3. Access still requires the shared account password, verified by Firebase

==============================================================================
STOPPING FIREBASE WARNING EMAILS:
==============================================================================

To stop receiving these emails:
1. Go to Firebase Console
2. Click the gear icon → Project Settings
3. Scroll to "Email preferences"
4. Uncheck "Security alerts and recommendations"

Note: This hides the warnings but doesn't fix the "issue" (which isn't
really an issue for your use case).
